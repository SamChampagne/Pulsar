## Today's slice plan

### Slice C0 — Drag infrastructure (foundation)

**Scope:** add `useGanttDrag` hook + drag state to `GanttBoard`. Track
mouse-down on a non-frozen bar, capture deltaX during mousemove, release on
mouseup. **No API call yet, no visual mutation** — just reads keyboard /
mouse and emits a `DragIntent` object that subsequent slices consume.

**Files (UI only):**
- Create: `ui/src/components/gantt/useGanttDrag.ts`
- Create: `ui/src/components/gantt/dragTypes.ts` (DragIntent, DragState types)
- Modify: `ui/src/components/GanttBoard.tsx` (wire the hook, no behaviour change)

**Definition of done:**
- TS build green.
- Existing Gantt UX unchanged (no visible regression).
- `DragIntent` event fires in console when a non-frozen bar is grabbed.
- Frozen bars do NOT emit `DragIntent` (defensive: respects existing
  `frozen` flag).

### Slice C1 — Visual ghost while dragging

**Scope:** while dragging, render a faint clone of the bar at the cursor's
projected position, snapped to a 15-minute grid. **Still no API call.** On
mouseup the ghost disappears and the bar snaps back. Pure visual feedback.

**Files (UI only):**
- Modify: `ui/src/components/GanttBoard.tsx` (render ghost from `DragState`)
- Modify: `ui/src/components/gantt/dragTypes.ts` (add `previewedStart`)

**Definition of done:**
- TS build green.
- Drag a bar horizontally → ghost follows the cursor on the same row, snaps
  to 15-min grid.
- Release → ghost vanishes, bar unchanged.
- No backend traffic.

### Slice C2 — Preview round-trip

**Scope:** on drop (mouseup), call `api.previewEdits()` with a single
`{edit_type: "move", operation_id, setup_start, start, end}` edit. Show a
modal "Preview move" with the delta (KPI changes, warnings count). User
confirms or cancels.

**Files:**
- Create: `ui/src/components/gantt/MovePreviewDialog.tsx` (modal: KPI delta,
  warnings list, [Apply] / [Cancel])
- Modify: `ui/src/components/GanttBoard.tsx` (on drop → open dialog)
- Modify: `ui/src/components/gantt/dragTypes.ts` (PreviewState)

**Definition of done:**
- TS build green.
- Drag → drop → modal opens with the preview KPIs (makespan delta, on-time
  delta, lateness delta, warnings count).
- Cancel: bar snaps back to original position.
- Apply button: disabled (slice C3 wires it).

### Slice C3 — Apply

**Scope:** Apply button calls `api.applyEdits()` with the same edit; on
success, refresh the dashboard / Gantt to show the candidate schedule. On
error, surface a Flash banner.

**Files:**
- Modify: `ui/src/components/gantt/MovePreviewDialog.tsx` (wire Apply
  callback)
- Modify: `ui/src/components/PlanningWorkbench.tsx` (route apply callback to
  candidate schedule reload)

**Definition of done:**
- TS build green.
- Drag → drop → preview → apply → Gantt re-renders against the new
  candidate schedule.
- New `candidate_schedule_id` set as the active candidate in app state
  (existing `setCandidateScheduleId`).
- Failed apply → Flash banner with the error message; bar snaps back.

## Architecture preservation

## Manual validation checklist (after slice C3)

1. Run `make stack-up`, log in, run a baseline.
2. Open `/gantt`.
3. Grab a non-frozen bar, drag horizontally → ghost follows snapping to
   15-min grid (slice C1 behaviour).
4. Drop → modal "Preview move" shows KPI delta + warnings (slice C2).
5. Click Apply → modal closes, Gantt re-renders against candidate (slice
   C3).
6. Grab a frozen bar → drag does nothing, cursor shows "not-allowed".
7. Cancel a preview → bar snaps back.
8. Trigger an apply error (e.g. infeasible move) → Flash banner.
