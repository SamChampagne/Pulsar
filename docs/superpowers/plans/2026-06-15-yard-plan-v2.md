# Yard Plan v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `/yard` into an interactive 2D yard plan — spots positioned on a snap grid, drag-and-drop to assign/move trailers, a context drawer (visit, dwell time, move log), and a layout-edit mode.

**Architecture:** Tiny schema add (`YardSpot.posX/posY`, display-only) + a bulk layout-save endpoint + visit-detail includes moves — all in the Yard module (my lane; the parallel agent avoids schema/API/my data models). The web rebuilds `/yard` around isolated components (`YardPlan`, `YardContextDrawer`) using native HTML5 drag-and-drop (no new dep). Occupancy/assignment logic is UNCHANGED (rule 34): the plan just calls existing `assign`/`move` endpoints; `posX/posY` never touch logic.

**Tech Stack:** NestJS + Prisma (`@pulsar/database`), `@pulsar/shared` (pure, vitest), SvelteKit 5 runes (ssr=false), jest e2e in `apps/api/test`.

**Templates to mirror:** the Yard module just shipped — `apps/api/src/modules/yard/**` (esp. `spots/spots.service.ts`, `visits/visits.service.ts`, `overview/yard-overview.service.ts`), web `apps/web/src/routes/(app)/yard/+page.svelte` (current board — you replace its body with the plan), `apps/web/src/routes/(app)/yard/gate/+page.svelte` (forms). For drawer/overlay pattern, check `$lib/components/ui` for a Drawer/Modal/Panel; if none, use a fixed right column.

**Infra notes (Windows):**
- API detached `node dist/main.js`; after API rebuild kill port-3000 PID and restart. NEVER `pnpm --filter @pulsar/api build` while `pnpm dev` runs.
- After migration, kill the detached API (DLL lock) before `pnpm db:generate`. Migrate: `pnpm --filter @pulsar/database exec dotenv -e ../../.env -- prisma migrate dev --name <name>`.
- `api()` web client tolerates empty 200/201 bodies. List endpoints cap pageSize 100.
- Demo data already in acme: site `WH-MTL` with spots `DOOR-1` (DOCK_DOOR) + `P-1` (PARKING).

## Task 5: Web — YardPlan component (canvas + drag-and-drop)

**Files:** Create `apps/web/src/lib/components/yard/YardPlan.svelte`.

**Read first:** `apps/web/src/routes/(app)/yard/+page.svelte` (current board shapes: `board.spots[].occupyingVisit`, `board.unassigned[]`), `$lib/components/ui` exports (Badge/Button/Card/Select), how other components take props + callbacks in Svelte 5 (`$props()`).

- [ ] **Step 1: Build the component**

Props (Svelte 5 `$props()`): `{ spots, unassigned, editing = false, onAssign, onMove, onOpenSpot, onLayoutChange }`.
- `spots`: array of `{ id, code, type, isActive, posX, posY, occupyingVisit }`.
- Compute grid bounds: `cols = Math.max(6, ...spots.map(s => (s.posX ?? 0) + 1))`, `rows = Math.max(4, ...)`.
- Render a `<div class="grid">` with `grid-template-columns: repeat(cols, minmax(120px, 1fr))` and explicit row count; CSS gap.
- **Placed spots** (`posX != null && posY != null`): a tile at `style="grid-column: {posX+1}; grid-row: {posY+1}"`. Tile shows: code, a type chip (DOCK_DOOR/PARKING/STAGING), and if `occupyingVisit` → visit number + trailer (unitNumber/plate or trailerRef) + direction + **dwell** (compute `formatDwell(now - new Date(occupyingVisit.checkInAt))` — pass `checkInAt` through the board occupant projection; if absent, omit dwell). Tone: free = neutral border, occupied = warn/filled, `!isActive` = muted.
- **Operation mode (`editing=false`):**
  - occupied tiles: `draggable=true`; on `dragstart` set `dataTransfer` payload `{ kind: 'visit', visitId, fromSpotId }`.
  - tiles: `ondragover` (preventDefault if free) + `ondrop`: read payload; if dropping a visit on a FREE tile → if payload.fromSpotId → `onMove(visitId, spot.id)` else `onAssign(visitId, spot.id)`; if tile occupied → `toast`-style no-op (the parent shows the error; or call a passed `onOccupiedDrop`). Keep it simple: only free tiles accept drops.
  - tile click (not drag) → `onOpenSpot(spot)`.
- **Edit mode (`editing=true`):** every tile `draggable`; on drop onto a grid cell, compute target `posX/posY` from the drop target's cell and call `onLayoutChange` with the updated positions array (parent holds the working copy). Unplaced spots (`posX==null`) render in a side "bac" `<div>` and are draggable onto the grid. (Implementation: make each grid CELL a drop target in edit mode; simplest = render an overlay of empty droppable cells, or compute nearest cell. To keep it robust, in edit mode render the full `cols×rows` set of empty cells as drop targets and position tiles over them.)

Keep the drag payload via `dataTransfer.setData('application/json', JSON.stringify(...))` and read in `drop`. Guard `dragover` with `e.preventDefault()` so `drop` fires.
