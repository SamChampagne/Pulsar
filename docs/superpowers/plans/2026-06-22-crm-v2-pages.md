# CRM v2 — Dashboard, Deals, Activities inbox, Company detail (Implementation Plan)

> REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** Flesh out the CRM module from 3 pages to a complete workspace: a CRM dashboard (home), a Deals table, an Activities/follow-ups inbox, and a dedicated company detail page — reusing the existing CRM API where possible.

**Architecture:** Add one read-only stats endpoint `GET /crm/overview` and extend `GET /crm/activities` with inbox filters; everything else reuses existing CRM endpoints. Five web routes + nav restructure. Branch: continue on `crm-module`.

**Tech Stack:** NestJS, Prisma, SvelteKit (Svelte 5 runes), `@pulsar/shared`, class-validator, jest e2e, svelte-check.

## Global Constraints
- Tenant isolation (rule 1): every query filters `tenantId` from `@CurrentUser()`.
- Endpoints gated `@RequireModule(MODULE_KEYS.CRM)` + `@RequirePermissions(crm.read|manage)` (rule 5). Lists `Paginated<T>`.
- Deal stage changes only via existing `POST /crm/deals/:id/advance` (rule 2) — new pages never write `stage` directly.
- Decimal `amount` serializes as a string over the wire — coerce to number in the web layer (this was the v1 pipeline bug).
- Web pattern: `$state` + single `$effect` load (untrack page reset, like the fixed companies/contacts pages), `api<T>()`, FR labels, Card/Badge/Table/FilterBar/PageHeader, tolerate empty bodies.
- Nav lives in `apps/web/src/lib/modules/navigation.ts` (CRM domain, key `crm`).
